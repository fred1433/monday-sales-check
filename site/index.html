      How this would run at Rove

      People would sign in with their Rove Google Workspace account. The portal would run on Cloud Run behind Identity-Aware Proxy, with access granted only to the Workspace groups you authorize.

      Partner workbooks and POS exports would land in a Cloud Storage bucket. The same pipeline would load them into BigQuery, with customer fields excluded before the load.

      Each role would read BigQuery views with row-level access: Michigan sales would read Michigan rows. Claude agents would reach the data through an MCP tool that only reads those views.

      The decision to settle first is which identity runs the query. It should be the person asking, or a service account limited to that role. A shared account with every right does not become Michigan because the screen says Michigan.

      Questions that would change the design before a pilot: who sends each export, who may see its detail, and what each source's contract allows, including use with a model provider.

      In this sample, the role travels in the request because sign-in is simulated, and the button replays the sample workbook's rows through a read-only API (Replay sample workbook). The behavior above is proven on fictional data, with tests. Workspace sign-in, IAM and your Google Cloud project would come with the pilot. Milestones: one market's files end to end, then the portal with sign-in and roles, then the reporting agent, then the next tools.
